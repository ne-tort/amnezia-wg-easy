# Удалённая установка по SSH

Один YAML-конфиг задаёт доступ по SSH и переменные для `.env` на сервере; скрипт выкладывает репозиторий и запускает `./deploy.sh`.

## Предусловия

- **Оператор:** Python 3.10+, `pip install -r requirements.txt`.
- **Сервер:** Docker Engine и **Docker Compose v2** (`docker compose version`), `git` (для режима `source.mode: git`).

На сервере должны быть открыты нужные порты: `22/tcp` (SSH), затем **`PANEL_HTTP_PORT`** (HTTP, по умолчанию 80), **`PANEL_HTTPS_PORT`** (HTTPS панели, по умолчанию 443), **`WG_PORT/udp`**. Имена переменных — как в [.env.example](../.env.example). Проверка облачного security group / внешнего файрвола — вручную; `install.py` проверяет только **слушатели на самом хосте** (см. ниже).

Для Let’s Encrypt домен `PANEL_DOMAIN` должен указывать на сервер; HTTP-01 использует тот хостовый порт, который проброшен на `80` внутри nginx (по умолчанию `PANEL_HTTP_PORT=80`).

## Быстрый старт

```bash
cd remote-deploy
pip install -r requirements.txt
cp config.example.yaml config.yaml
# Отредактируйте config.yaml (хост, ключ или пароль, env)
python install.py
```

По умолчанию берётся **первый существующий** файл в каталоге `remote-deploy/`: `config.yaml`, иначе `deploy-runtime.yaml`, иначе ожидается `config.yaml` (скопируйте из `config.example.yaml`). Явный путь: `python install.py -c config.yaml`.

Таймаут установления TCP-соединения SSH — 5 с. На **удалённом** хосте команды оборачиваются в GNU **`timeout`** (если установлен), чтобы зависший Docker/`ss` не блокировал сессию бесконечно; для `./deploy.sh` лимит 2 часа. Код выхода **124** на сервере означает срабатывание `timeout`.

Проверка без SSH (`--dry-run`): вывод сгенерированного `.env` с замазанными секретами, целевых портов и список шагов.

```bash
python install.py --dry-run
```

**Чужие контейнеры** скрипт **не** останавливает. Если порты заняты другим ПО — освободите их вручную на сервере и снова запустите `install.py`.

**Preflight портов** (после остановки **только** своего compose-стека в `remote.path`): проверяется, что UDP `WG_PORT` и TCP `PANEL_HTTP_PORT` / `PANEL_HTTPS_PORT` свободны **или** уже принадлежат контейнерам этого же проекта. Иначе установка **прерывается** с сообщением. Обход: **`--skip-port-check`** (только если уверены, что порты свободны).

```bash
python install.py --skip-port-check
```

## Повторный запуск (обновление)

Порядок на сервере: синхронизация кода (git/tar) → **`docker compose down`** только для этого репозитория (`docker-compose.yml` в `remote.path`) — тома **не** удаляются (`-v` не используется) → preflight портов → запись `.env` → **`./deploy.sh`**.

Так останавливаются только контейнеры **этого** compose-проекта. Затем `deploy.sh` пересобирает образы и поднимает стек с актуальным кодом и новым `.env`.

Проверка без SSH: `python install.py --dry-run` — в выводе видны те же шаги.

## Конфигурация

- **`ssh`:** `host`, `user`, опционально `port` (по умолчанию 22). Аутентификация: **`identity_file`** (предпочтительно) или **`password`**, либо **`ssh_password_env`** — имя переменной окружения на машине оператора, откуда взять пароль.
- **`source.mode`:** `git` — `git clone` / `git pull` в `remote.path`; `local` — архив текущего дерева репозитория без каталога `remote-deploy` (чтобы не утащить `config.yaml`).
- **`remote.path`:** каталог на сервере с репозиторием (например `/opt/amnezia-wg-easy`).
- **`env`:** пары `KEY: value` как в корневом `.env` (имена **в верхнем регистре**, как в [.env.example](../.env.example)). Переопределяют значения по умолчанию из `.env.example`.

**`WG_HOST` и Endpoint VPN:** это хост, который попадает в клиентские конфиги как `Endpoint = WG_HOST:WG_PORT` (см. `src/lib/WireGuard.js`, синхронизация с БД в `src/server.js`). **`PANEL_DOMAIN`** задаёт только HTTPS для веб-панели и **не подставляется** в Endpoint автоматически: если нужен домен в VPN, укажите его явно в **`WG_HOST`** (или оставьте публичный IP).

При каждом успешном запуске `install.py` файл **`{remote.path}/.env` на сервере полностью перезаписывается** сгенерированным содержимым из секции `env` (строка «Generated by remote-deploy/install.py» в шапке файла). Повторная установка на том же сервере подхватывает актуальные значения из YAML, в том числе **`WG_HOST`** — его можно менять между запусками для смены Endpoint.

Затем на сервере выполняется `./deploy.sh`: он **не затирает** явно заданный не-локальный `WG_HOST`. Авто-подстановка публичного IP через `ifconfig.me` срабатывает только если `WG_HOST` пустой/плейсхолдер или остался `127.0.0.1`/`localhost` при **нелокальном** `PANEL_DOMAIN` (см. [deploy.sh](../deploy.sh)).

Где ещё используется `WG_HOST` в репозитории: `src/config.js`, `src/lib/WireGuard.js`, `src/lib/Server.js`, `src/server.js`, `docker-compose.yml`, [deploy.sh](../deploy.sh), [nginx/entrypoint.sh](../nginx/entrypoint.sh) (fallback для `PANEL_DOMAIN`).

**`LANGUAGE`** (`ru` или `en`): попадает в `.env` на сервере; при старте контейнера панели значение записывается в `app_settings` и используется **`GET /api/lang`** как язык по умолчанию (после каждого деплоя с непустым `LANGUAGE` в YAML он перезаписывает запись в БД).

Если в `env` заданы **`ADMIN_USERNAME`** и **`ADMIN_PASSWORD`** (пароль не короче 5 символов), после успешного `./deploy.sh` `install.py` выполняет в контейнере `amnezia-wg-easy` скрипт `node scripts/applyAdminPasswordFromEnv.js`: хеш пароля в SQLite для этого пользователя перезаписывается из переменных окружения контейнера (те же значения, что попали из сгенерированного `.env`). Так пароль админа в БД остаётся согласованным с YAML при каждом деплое. Если пароль в конфиге пустой или слишком короткий, скрипт только пишет в stderr `skip` и завершается с кодом 0. Если пользователь с именем `ADMIN_USERNAME` не найден (или неактивен), скрипт завершается с ошибкой и `install.py` падает — проверьте опечатку в имени.

Подстановка из окружения оператора: в YAML можно использовать строки вида `${ENV:VARNAME}` (например для пароля SSH).

## Безопасность

- Не коммитьте `config.yaml` с паролями (см. `.gitignore`).
- Предпочитайте вход по SSH-ключу вместо пароля.
