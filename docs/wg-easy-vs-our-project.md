# Отличия от оригинального wg-easy

Тезисно: что было добавлено и изменено относительно **оригинального wg-easy** (проект, от которого ответвился amnezia-wg-easy), что это даёт, зачем нужно, как изменило архитектуру и модель использования.

---

## 1. Исходный wg-easy — что это

- Веб-интерфейс для управления WireGuard: создание клиентов, выдача конфигов, QR, скачивание.
- Один пароль на вход (или без авторизации); один интерфейс (wg0).
- Конфиг WireGuard генерируется и записывается в файл (например `wg0.conf`); клиенты хранятся в конфиге/БД в зависимости от ветки.
- Цель: быстро поднять свой VPN за пару минут, раздавать конфиги пользователям.
- Со временем часть веток (например актуальный wg-easy) перешла на Nuxt, SQLite, мультипользователей, 2FA, one-time links — то есть в сторону «панели как сервиса».

---

## 2. Надстройка amnezia-wg-easy (первый слой отличий)

**Что добавлено / изменено**

| Изменение | Что даёт | Зачем |
|-----------|----------|--------|
| Подмена стека WireGuard на **AmneziaWG** (демон + awg/awg-quick) | Трафик маскируется под другой протокол (например QUIC), обход DPI. | В условиях блокировок обычный WireGuard легко детектируется; AmneziaWG добавляет обфускацию. |
| Параметры **S3, S4** в конфиге | Padding cookie/transport — часть обфускации по спецификации Amnezia. | Без них конфиг не соответствует протоколу AmneziaWG. |
| Параметр **I1** (подпись, напр. QUIC Initial) в клиентском конфиге | Первый пакет «притворяется» выбранным протоколом. | DPI видит «похожий на QUIC/DNS» трафик вместо явного WireGuard. |
| **H1–H4, Jc, Jmin, Jmax** и др. в конфиге | Заголовки и junk-пакеты по документации Amnezia. | Полное соответствие формату AmneziaWG; без них обход неполный или нерабочий. |
| Образ Docker на базе **amneziavpn/amneziawg-go** | На сервере крутится именно AmneziaWG, а не vanilla WireGuard. | Иначе обфускация не применяется. |

**Итог слоя:** продукт перестаёт быть «просто веб-мордой к WireGuard» и становится «веб-мордой к AmneziaWG с фокусом на обход блокировок». Архитектура «один конфиг / один интерфейс» может сохраняться; меняется только бэкенд (демон и формат конфига).

## 3. Наш форк (amnezia-wg-fresh) — второй слой отличий

**Что добавлено / изменено**

| Изменение | Что даёт | Зачем |
|-----------|----------|--------|
| **Профили маскировки** (QUIC, DNS, SIP, STUN, WebRTC, DTLS) | Выбор протокола под ситуацию; короткие подписи (DNS, STUN и т.д.) — меньше размер конфига, читаемый QR. | В оригинале amnezia — по сути один I1 (QUIC); разная цензура по странам/провайдерам; один fingerprint рискован. |
| **Уровни I0–I5** в UI | Явный выбор: без подписи (I0), только I1 (I1), или цепочка I1→I2→…→I5 по рекомендациям Amnezia. | Пользователь сам выбирает уровень обфускации; I0 — совместимость/минимальный трафик. |
| **QR только для профилей с короткой подписью**; для QUIC/SIP — только «Скачать» | QR не перегружен, камера нормально читает. | Длинный I1 (QUIC) в QR даёт нечитаемый или не помещающийся код. |
| **Компактный QR по умолчанию выключен** | По умолчанию конфиг в QR с I1 (полный обход); компактный режим — опция (`WG_QR_COMPACT=true`). | Предсказуемое поведение: «сканировал QR — получил полный конфиг». |
| **Кнопка профиля скрыта при I0**; порядок кнопок: сначала I, потом профиль | Меньше путаницы: при I0 выбор протокола не показывается; порядок «сначала уровень, потом протокол». | UI отражает логику: уровень важнее, профиль — уточнение. |
| **deploy.sh** — авто подстановка внешнего IP и генерация пароля | Первый запуск без ручного редактирования .env. | Упрощение деплоя для неспециалистов. |
| **Один JSON (wg0.json)** как единственное хранилище состояния | Нет БД, миграций, бэкап — один файл. | Минимализм; для сценария «одна панель, один админ» достаточно. |
| Volume и путь **/etc/amnezia/amneziawg** | Конфиг и ключи лежат в предсказуемом месте, отдельно от «голого» WireGuard. | Разделение AmneziaWG и классического WG при необходимости. |

**Итог слоя:** продукт заточен под «один self-hosted сервер, один админ, максимум обхода при минимуме настроек»; UI и логика приведены в соответствие с профилями и уровнями обфускации.

## 4. Изменения архитектуры (от wg-easy к нашему проекту)

- **Хранилище:** в развитых ветках wg-easy — БД (SQLite и т.п.), сущности (клиенты, пользователи, настройки). У нас — один файл `wg0.json`; конфиг WireGuard/AmneziaWG собирается из него. Нет миграций схемы, бэкап = копия файла.
- **Авторизация:** в wg-easy может быть несколько пользователей, роли, 2FA. У нас — один пароль из env (`PASSWORD`), одна сессия. Нет мультитенантности.
- **Бэкенд протокола:** вместо демона WireGuard — демон AmneziaWG + утилиты awg/awg-quick; формат конфига расширен (S3, S4, I1–I5, H1–H4 и т.д.).
- **Генерация конфига клиента:** не только ключи и Endpoint, но и выбор профиля (I1), уровня (I0–I5), подстановка цепочки I2–I5; логика QR зависит от длины подписи.
- **Деплой:** акцент на один скрипт (`deploy.sh`) и docker compose без обязательного ручного ввода IP/пароля при первом запуске.

Итого: архитектура **упрощена** по сравнению с «большим» wg-easy (один конфиг, один пароль, один админ) и **усложнена** в части протокола (AmneziaWG, профили, уровни).

---

## 5. Бизнес-модель и модель использования

- **Оригинальный wg-easy:** инструмент для быстрого поднятия своего VPN; часть форков развилась в сторону SaaS-панели (много пользователей, подписки, one-time links).
- **Amnezia-wg-easy:** тот же self-hosted инструмент, но с фокусом на обход блокировок (AmneziaWG, DPI).
- **Наш проект:** сознательно остаётся **инструментом для себя**, а не платформой для продажи доступа. Один инсталл = один админ, один пароль, один JSON. Целевой сценарий: поднять сервер у себя или у провайдера, выдать конфиги близким/команде, при необходимости менять профиль и уровень обфускации под конкретную цензуру. Монетизация и мультитенантность не заложены; «бизнес-модель» — минимальные затраты на поддержку и деплой при максимальной пригодности под обход DPI.

**Кратко:** от wg-easy мы ушли в сторону «одна панель под один сервер и одного владельца», но добавили полноценную поддержку AmneziaWG, выбор протокола маскировки и уровней обфускации, чтобы продукт оставался простым в эксплуатации и при этом эффективным в условиях блокировок.
