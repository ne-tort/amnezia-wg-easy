# Jmin / Jmax — размер junk-пакетов

## Смысл

Каждый junk-пакет имеет случайный размер в байтах из `[Jmin, Jmax]`. Вместе с `Jc` задаёт «облако» перед handshake.

## Hard limits

- `0 ≤ Jmin < Jmax ≤ 1280` (практический потолок MTU-подобных значений в доках Amnezia)
- Рекомендации ядра часто: Jmin≈8, Jmax≈80 — это **минимум** для совместимости, не оптимум против DPI
- Architect: `jmax > jmin + 64`; для AWG 1.0 `jmax > 81`

## Адекватные рамки (по intensity Architect)

| Intensity | Jmin | Jmax |
|-----------|------|------|
| low | 64–256 | 256–512 |
| medium | 128–512 | 512–1024 |
| high | 256–768 | 768–1280 |

Панель для DNS держит диапазон ближе к **low**, для QUIC/DTLS — ближе к **medium**.

## Влияние

- Узкий/маленький диапазон — похоже на короткий probe (DNS/STUN), меньше overhead.
- Широкий/большой — больше похоже на bulk/QUIC Initial, выше расход на коннект.

## Панель

При генерации: `jmax = max(rolled, jmin + 64)` и clamp в protocol ranges. Env-дефолты панели исторически были `JMIN=64`, `JMAX=1000` (фиксированные) — seed ranges заменяют это для рандома.
