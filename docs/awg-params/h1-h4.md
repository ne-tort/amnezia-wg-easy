# H1–H4 — magic headers

## Смысл

Заменяют стандартные идентификаторы типов сообщений WireGuard:

| Поле | Тип |
|------|-----|
| H1 | Initiation |
| H2 | Response |
| H3 | Cookie |
| H4 | Transport |

Без совпадения H на клиенте и сервере handshake не состоится.

## Hard limits

- Рекомендовано: **5 … 2147483647** (INT32_MAX) для совместимости клиентов
- H1…H4 **должны различаться**; в режиме ranges — **непересекающиеся** интервалы
- AWG 2.0 предпочитает ranges; userspace **amneziawg-go** в панели часто принимает только **single int** — `__hToSingle()` при записи `awg0.conf` берёт случайное число из range, если передали `"a-b"`

## Адекватные рамки для панели

Режим `h.mode = "single"`: четыре **различных** int из непересекающихся четвертей пула `[min, max]`:

1. зона 1/4 → H1  
2. зона 2/4 → H2  
3. зона 3/4 → H3  
4. зона 4/4 → H4  

Так гарантируется уникальность без полноценных ranges в конфиге go.

## Влияние

Уникальные H ломают сигнатуру «тип сообщения = 1/2/3/4». Пересечение H недопустимо и приводит к поломке протокола.
