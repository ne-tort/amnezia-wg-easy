# Инварианты и валидация

Генератор и `POST …/obfuscation/apply` отклоняют набор, нарушающий правила.

## Обязательные

1. `1 ≤ Jc ≤ 128` (в панели обычно 4–12)
2. `0 ≤ Jmin < Jmax ≤ 1280`
3. `Jmax ≥ Jmin + 64` (рабочее правило Architect)
4. Для совместимости AWG 1.0: `Jmax > 81` когда Jc≥4
5. `S1 + 56 ≠ S2`
6. `S2 + 92 ≠ S3`
7. `0 ≤ S4 ≤ 32`
8. `S1,S2 ∈` своих protocol ranges; `S3 ≤ 64` (non-extreme)
9. `H1,H2,H3,H4` — четыре различных целых в `[5, 2147483647]`

## Сервер ↔ клиент

Активные Jc/Jmin/Jmax/S*/H* на `awg0` и в клиентском conf **обязаны совпадать**. Разные клиенты не могут одновременно иметь разные *активные* junk-наборы на одном интерфейсе.

## CPS (I1–I5)

Не часть junk-ranges JSON. Валидность — наличие `i1` (и опциональных слотов) в `signatures.json` для пары `profile#signature`.
