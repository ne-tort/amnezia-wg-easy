# Оригинальный проект Amnezia и соответствие протокола

## Где находится оригинальный Amnezia (протокол)

Организация: **https://github.com/amnezia-vpn**

| Репозиторий | Назначение |
|-------------|------------|
| **amnezia-vpn/amneziawg-go** | Ядро протокола AmneziaWG: userspace-реализация на Go (форк WireGuard-Go), обфускация от DPI. |
| **amnezia-vpn/amneziawg-tools** | Утилиты конфигурации: `wg`, `wg-quick` (awg, awg-quick), парсинг .conf и UAPI к демону. |
| **amnezia-vpn/amneziawg-linux-kernel-module** | Модуль ядра Linux (альтернатива userspace). |
| **amnezia-vpn/amnezia-client** | Десктоп/мобильный клиент (C++), без веб-админки. |

Документация протокола: [AmneziaWG | Amnezia Docs](https://docs.amnezia.org/documentation/amnezia-wg).

## Что у нас в стеке

- **Docker-образ:** `FROM amneziavpn/amneziawg-go:latest` — это официальный образ, в котором:
  - Собран **amneziawg-go** (демон AmneziaWG).
  - Установлены **amneziawg-tools** (awg, awg-quick), симлинки `wg` → `awg`, `wg-quick` → `awg-quick`.
- Конфиг пишется в `wg0.conf` и применяется через `wg syncconf wg0 <(wg-quick strip wg0)` — то есть используются те же утилиты и тот же демон, что в оригинальном проекте.

**Вывод:** на сервере используется актуальная userspace-реализация AmneziaWG из официального репозитория (образ amneziawg-go + amneziawg-tools). Ядро протокола — то же, что в оригинале.

## Формат конфига и соответствие

Параметры из [README amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go) и разбора `amneziawg-tools/src/config.c` и `amneziawg-go/device/uapi.go`:

| Параметр | Оригинал (amneziawg-go / amneziawg-tools) | Наш форк |
|----------|-------------------------------------------|----------|
| **Jc** | int, рекомендуемый диапазон 4–12 | Есть, из env или random 4–12 |
| **Jmin, Jmax** | int, Jmin ≤ Jmax; docs: 64–1024 байт для junk | Есть (JMIN=64, JMAX=1000 по умолчанию) |
| **S1** | padding init message | Есть |
| **S2** | padding response message | Есть |
| **S3** | padding cookie message | Есть |
| **S4** | padding transport messages | Есть |
| **H1–H4** | строка: одно значение `"1234"` или диапазон `"123-456"` | Унифицированы: по умолчанию один диапазон `1-2147483647` для всех четырёх (случайный заголовок на пакет — лучше для обфускации). Через env можно задать своё значение или диапазон. |
| **I1–I5** | custom signature packets (теги `<b 0x...>`, `<r size>` и т.д.) | В клиентском конфиге выдаём только **I1**. I2–I5 опциональны (см. ниже). |

- На **сервере** в `wg0.conf` мы не пишем I1–I5 (по рекомендации README: custom signature обычно только на клиенте).
- Имена ключей в .conf совпадают с ожиданиями amneziawg-tools; регистр и набор полей совместимы.

## I2–I5: зачем нужны, нужны ли

**Что это:** пакеты «кастомной подписи», которые шлются перед каждым handshake (в порядке I1 → I2 → I3 → I4 → I5). Собираются из тегов вида `<b 0x...>` (статические байты), `<r size>` (случайные байты), `<t>` (timestamp) и т.д. и маскируют трафик под другой протокол (например, QUIC у I1).

**На что влияют:** только на обфускацию: чем больше разных «подписей», тем сложнее паттерн для DPI. На криптостойкость и корректность протокола не влияют.

**Нужны ли:**  
- **I1** — основной вариант для обхода DPI (часто используют «квази-QUIC» подпись). Для большинства сценариев **достаточно одного I1**; у нас он есть по умолчанию.  
- **I2–I5** — опциональные дополнительные пакеты. В оригинале: «if no value specified, the packet is skipped». То есть они **не обязательны**, а доп. обфускация.

**Где используются:** только в **клиентском** конфиге. Сервер (wg0.conf / amneziawg-go) I1–I5 не хранит и не проверяет — он принимает соединение после обфусцированного handshake. Клиент по своему конфигу отправляет пакеты подписей (I1 → I2 → … → I5) перед handshake; серверу не нужно «знать» их содержимое.

**Обязательно ли задавать:** I1 — да, обычно задаётся (у нас по умолчанию QUIC-подпись). I2–I5 — нет: пустое значение = пакет не отправляется.

**Можно ли менять в любой момент:** да. Параметры I2–I5 в админке — это шаблон для **новых** выданных конфигов. Изменение сохраняется в wg0.json и применяется ко всем последующим скачиваниям/просмотрам конфига. Уже выданные конфиги у пользователей не обновляются; старые клиенты продолжают работать со своими I2–I5. Перезапуск сервера не требуется.

**Рекомендация:** оставляем только I1. I2–I5 не нежелательны (лишнего трафика немного), но и не дают принципиального выигрыша при типичном DPI; добавляют длину конфига и усложняют настройку. Имеет смысл подключать I2–I5 только при явной необходимости (очень жёсткий DPI, нужна имитация нескольких протоколов). Унифицировать или добавлять I2–I5 в веб-админке не обязательно.

## H1–H4: унификация

По умолчанию для **H1, H2, H3, H4** задаётся один и тот же диапазон **`1-2147483647`** (допустимый int32). В таком виде amneziawg-go для каждого пакета выбирает случайное значение заголовка в этом диапазоне, что улучшает обфускацию по сравнению с фиксированным числом. Через переменные окружения `H1`–`H4` можно задать свой диапазон (например, `100-200`) или одно значение (например, `1234`). Существующие конфиги с сохранёнными числовыми h1–h4 продолжают работать (в .conf пишется то, что в конфиге).

## H и L: примеры, рекомендации, под L1 QUIC

**Источники:** [AmneziaWG | Amnezia Docs](https://docs.amnezia.org/documentation/amnezia-wg), [README amneziawg-go](https://github.com/amnezia-vpn/amneziawg-go), [wg-easy Amnezia](https://wg-easy.github.io/wg-easy/v15.2/advanced/config/amnezia/), обсуждения в issues (amneziawg-go #42, kernel module #119).

### Готовые конфигурации и H1–H4

- **Публичных «готовых» наборов H1–H4 под QUIC нет.** Разработчики Amnezia намеренно не документируют конкретные значения заголовков, чтобы усложнить создание универсальных правил DPI.
- В части реализаций при **фиксированных** значениях требуется **уникальность**: H1, H2, H3, H4 должны отличаться друг от друга; в некоторых источниках указан диапазон значений **5–2147483647**.
- **Диапазон вместо одного числа** даёт лучшую обфускацию: каждый пакет получает случайный заголовок из диапазона, нет стабильного отпечатка. Наш дефолт **`1-2147483647`** для всех четырёх — разумный выбор: максимальная энтропия, без привязки к одному протоколу.
- **Под L1 (QUIC):** I1 уже задаёт QUIC-подпись; отдельной «QUIC-специфичной» настройки H в официальной документации нет. Использование одного широкого диапазона для H1–H4 совместимо с маскировкой под QUIC.

### Уровни I (I0–I5)

- **I0** — без I1–I5 (минимальная обфускация, совместимость с AmneziaWG 1.0).
- **I1** — только I1 (QUIC-подпись); достаточно для большинства сценариев.
- **I2** — I1 + I2=\<c\> (счётчик пакетов, динамика).
- **I3** — I1 + I2=\<c\> + I3=\<t\> (timestamp, динамика).
- **I4** — I1 + I2=\<c\> + I3=\<t\> + I4=\<r N\>.
- **I5** — I1 + I2=\<c\> + I3=\<t\> + I4=\<r N\> + I5=\<r N\>. N задаётся через `OBFS_R_BYTES` (по умолчанию 48). Цепочка по рекомендациям: без фиксированного fingerprint.

### Рекомендуемые диапазоны параметров (по документации)

| Параметр | Рекомендация | Наш дефолт |
|----------|--------------|------------|
| **Jc** | 4–12 (README amneziawg-go) | random 4–12 |
| **Jmin, Jmax** | 64–1024 байт (docs.amnezia для junk) | JMIN=64, JMAX=1000 |
| **S1, S2** | 0–64 байт (docs.amnezia) | random 15–150 (допустимо, больше вариативности) |
| **H1–H4** | диапазон или уникальные фиксированные 5–2147483647 | один диапазон `1-2147483647` |

Junk-пакеты (Jc, Jmin, Jmax) рекомендуется использовать **только на клиенте** (README). Значения S1–S4 и H1–H4 **должны совпадать** на сервере и клиенте (wg-easy).

## Практические рекомендации 2025–2026 (QUIC-реалистичный профиль)

Оценка текущего дефолта и альтернативный «QUIC-реалистичный» профиль, распространённый в практике.

### Что означает текущая конфигурация

- **I1** — статический QUIC Initial из документации Amnezia (~1.5 KB). **Минус:** публичный и массовый; продвинутый DPI может его отпечатать. В 2025–2026 это основной риск: статичный I1 = потенциальная сигнатура.
- **I2–I5** — при уровне I1 не задаются; при уровнях I2–I5 в конфиг подставляется динамическая цепочка: I2=\<c\>, I3=\<t\>, I4=\<r N\>, I5=\<r N\> (без фиксированного отпечатка).
- **H1–H4 = 1–2147483647** — максимальная энтропия заголовков, но **не QUIC-реалистично**: у QUIC заголовки имеют структуру (флаги, версия, DCID/SCID и т.д.), а не random int32. Получается высокоэнтропийный UDP, а не правдоподобный QUIC.
- **QR** — compact-режим (без I1) корректен: полный конфиг раздавать через файл.

### Рекомендации практиков 2025–2026

1. **Не использовать публичный I1**  
   Лучше снять свой QUIC Initial с реального трафика (браузер, CDN — Cloudflare, Google, YouTube) и задать его через env: `I1=<b 0x...>`.

2. **Как получить свой I1**  
   Wireshark → фильтр `udp.port == 443 && quic` → открыть сайт на QUIC (YouTube, Google) → найти **Initial** packet (не Short Header, не Retry) → Copy → as Hex Stream → вставить как `I1=<b 0x....>`. Не брать пакет больше MTU.

3. **Динамическая цепочка I2–I5**  
   Для вариативности без фиксированного отпечатка рекомендуют:  
   `I2=<c>` (счётчик), `I3=<t>` (timestamp), `I4=<r N>`, при необходимости `I5=<r N>`.  
   В нашем UI при выборе уровня I2–I5 в конфиг подставляется именно эта цепочка: I2=\<c\>, I3=\<t\>, I4=\<r N\>, I5=\<r N\> (N задаётся через `OBFS_R_BYTES`, по умолчанию 48).

4. **H1–H4 не в полном int32**  
   Для «выглядеть как QUIC» часто советуют узкий диапазон, например **1–4096**, или фиксированные небольшие значения. Задать через env: `H1=1-4096`, `H2=1-4096`, `H3=1-4096`, `H4=1-4096`.

5. **Jc / Jmin / Jmax**  
   В «оптимальном» QUIC-профиле часто указывают: Jc = 6–10, JMIN = 64–512, JMAX = 512–1200. Наши дефолты (Jc 4–12, JMIN=64, JMAX=1000) близки; при желании сузить — через env.

### Минимально адекватный QUIC-реалистичный профиль (архитектурно)

| Параметр | Рекомендация |
|----------|--------------|
| I1 | Свой QUIC Initial из Wireshark (`<b 0x...>`) |
| I2 | `<c>` |
| I3 | `<t>` |
| I4 | `<r N>` (N = OBFS_R_BYTES, по умолчанию 48) |
| I5 | `<r N>` (при уровне I5) или пусто в минимальном профиле |
| Jc | 6–10 |
| Jmin, Jmax | 64–512, 512–1200 |
| H1–H4 | `1-4096` (узкий диапазон) |

**Важно:** DPI смотрит не только первый пакет, но и последовательность, интервалы, поведение после Initial. Amnezia снижает вероятность детекта, но не гарантирует обход продвинутого DPI.

## Расширение на другие протоколы (DNS, SIP и др.)

AmneziaWG может маскировать трафик под разные UDP-протоколы: **QUIC, DNS, SIP и другие**. Механизм один и тот же: в **I1** подставляется hex-снимок реального пакета выбранного протокола в формате `<b 0x...>`. Цепочка I2–I5 (\<c\>, \<t\>, \<r N\>) протоколонезависима и подходит для любого I1.

### Общий способ извлечения подписи (любой протокол)

По [документации Amnezia](https://docs.amnezia.org/documentation/instructions/new-amneziawg-selfhosted/#how-to-extract-a-protocol-signature-for-amneziawg-manually):

1. **Wireshark** → выбрать интерфейс → начать захват.
2. В фильтр ввести имя протокола (например `quic`, `dns`, `sip`) или `udp` для просмотра всего UDP.
3. Выбрать пакет (рекомендуют **начальный или конечный** в сессии — они лучше маскируют handshake).
4. ПКМ по пакету → **Copy → … as Hex Stream**.
5. Оформить строку для I1: префикс `<b 0x`, затем hex без пробелов, в конце `>`. Пример: `<b 0xc70000000108ce1b...>`.

Размер пакета не должен превышать MTU (обычно 1500). Лучше использовать **собственный** захват (свой браузер, свой DNS-запрос), а не публичные примеры — чтобы не создавать массовый fingerprint.

### Рекомендации по протоколам

| Протокол | Фильтр Wireshark | Что брать | Примечание |
|----------|-------------------|-----------|------------|
| **QUIC** | `quic` или `udp.port == 443` | **Initial**-пакет (не Short Header, не Retry) | Типичный выбор; пакет большой (~1–1.5 KB). Сайты на QUIC: YouTube, Google, Cloudflare. |
| **DNS** | `dns` или `udp.port == 53` | Первый пакет запроса (DNS query): заголовок 12 байт + вопрос | Пакеты небольшие; часто меньше цензурируются. Удобно для «тихого» трафика. |
| **SIP** | `sip` или порт 5060 (UDP) | Начальный запрос сессии (например REGISTER, INVITE) | Используется в VoIP; может быть реже в фокусе DPI. |
| **Другие** | По имени протокола или порту | Начальный/конечный пакет сессии | Любой UDP-протокол: тот же приём — скопировать hex и подставить в I1. |

- **DNS:** запрос клиента (query) — первый пакет в обмене; в Wireshark виден как DNS с полем «Query». Размер обычно десятки байт (заголовок 12 байт + длина домена и т.д.).
- **SIP:** типично порт 5060 (UDP); выбрать первый пакет запроса (REGISTER, INVITE и т.д.) и скопировать как Hex Stream.
- **QUIC:** уже описан выше (Initial, порт 443).

### Что менять в нашем проекте при расширении

- **I1** задаётся через env `I1=<b 0x...>`. Для «профиля» под DNS или SIP пользователь сам снимает пакет и подставляет строку; можно не хранить готовые публичные DNS/SIP-подписи (риск fingerprint).
- В документации или в UI можно добавить короткую инструкцию: «Под другой протокол (DNS, SIP): Wireshark → фильтр по протоколу → Copy as Hex Stream → I1=<b 0x...>», со ссылкой на [официальную инструкцию Amnezia](https://docs.amnezia.org/documentation/instructions/new-amneziawg-selfhosted/#how-to-extract-a-protocol-signature-for-amneziawg-manually).
- Уровни I2–I5 и цепочка \<c\>, \<t\>, \<r N\> **общие** для всех протоколов; отдельные настройки под DNS/SIP для I2–I5 в документации не требуются.

### Итог по текущему дефолту

Конфигурация **работает**; при уровнях I2–I5 в конфиг подставляется рекомендуемая цепочка I2=\<c\>, I3=\<t\>, I4/I5=\<r N\>. Для ещё более аккуратного варианта: заменить I1 на собственный (Wireshark) и при желании сузить H до 1–4096. См. комментарии в `src/config.js`.

- **Ядро протокола:** то же, что в оригинале — образ `amneziavpn/amneziawg-go` и утилиты из amneziawg-tools.
- **Формат конфига:** совпадает с ожиданиями amneziawg-go и amneziawg-tools (Jc, Jmin, Jmax, S1–S4, H1–H4, I1; при желании можно добавить I2–I5 и диапазоны для H).
